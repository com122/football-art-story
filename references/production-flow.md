# 两轮制作归纳的迭代流程

## 接手现有作品

先定位当前交付HTML、配置、已选画稿、笔触几何和项目状态；以用户最新选定版本为基准。用户说“只换人物／画法”“下面字更大”“把章节分开”，不意味着改动作、重画背景或扩写内容。

最小项目记录可包括：当前产物路径；每章采用的源图和几何；身份／时期／姿势锚点；最新要求；淘汰素材及原因；已完成与待验证；来源核验时间。接受一项更正时同步修订记录，明确撤销旧判断。不要把暂停说明留成恢复后的唯一入口。

两轮中的关键教训：

| 反馈 | 可复用的处理 |
|---|---|
| “像照片贴上去”“没有一笔一笔画” | 观看实际中段，检查是否局部标记累积；静态完成帧不能证明动画合格 |
| “换画法不是换动作” | 同一来源固定姿态、头部与五官位置，再改变线条和涂色 |
| 概括、第二档、精画差别不明显 | 保留概括／精画两档，独立准备对应画稿；粗线简笔画另列 |
| 钢笔脸黑、黑衣一团 | 保留皮肤留白、衣服受光面和轮廓分区；不把彩色排线统一涂黑 |
| 画面有多余的手 | 回看原照片肢体归属；以最新更正为准，定点修正后逐只复核 |
| 为露全鞋导致身体变矮 | 保持自然比例；有裁切授权时自然出画，不纵向压缩 |
| 白色墙被涂成大片蓝色 | 明确背景自身材质和颜色；白墙保持暖白／浅灰，不沿用球队主色覆盖 |
| “白色里混一点红蓝” | 颜料夹在白色刷痕和刀痕中，分散且少量；不做左红右蓝的大角块 |
| 下方小字看不见 | 在实际观看尺寸检查；正文约40–48px，浅底近黑字，删去无叙事作用的照片脚注 |
| 画完后等太久／没画完就走 | 用真实终笔而非固定计时截断；一般画完停1秒 |

这些是对应反馈的处理方式，不是每个新项目都必须生成一套新的画法比较、换球员实验或外部Agent测试。

## 有用的制作顺序

1. 根据当前范围选：只改旧片、单张试画、封面小样、完整生涯、分章输出。已有足够选择时直接做，不重复询问。
2. 先核实会影响画面的时期、球衣与身份；按叙事需要选择清晰参考。独立人物尽量避免多人遮挡；合影按用户指定保留人物。
3. 准备一张与目标画法匹配的画稿。强媒介造型应在画稿阶段成立，提取器只负责把现有笔法转成可逐笔回放的几何。
4. 比较源画稿、实际绘画中段和实际完成帧。人物／构图不合格时先修源稿，不在排版层用拉伸或滤镜遮盖。
5. 复用已通过的引擎和排版扩展到其余章节。记录各章实际时间；文字和数据口径写入配置，来源留在影片外。
6. 依请求交付完整HTML、独立章节、MP4或ZIP。只改交付格式时不再生成图片。

静态小样、逐笔动画、真人连续运动视频是三个不同交付层级。报告实际完成的层级和工具能力；参考视频找不到干净的视角时，说明遮挡与补画的影响，不把不可靠的人偶关节动画当作替代成果。

## 更新 Skill

从真实反馈提炼会改变决策的规则，不把某一球员的号码、赞助、年龄或奖项写成默认。可重复执行的薄弱环节写成脚本；只讲审美判断的部分保留可观察验收标准。更新现有Skill前存档，保留原始项目；检验新脚本和旧入口后再同步本地安装版。
