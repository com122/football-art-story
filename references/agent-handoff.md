# 交给其他 Agent 复用

用户明确要求外部测试时，其他产品不一定自动识别 Codex 的安装目录，明确提供本 Skill 文件夹或压缩包。先让对方读 SKILL.md，再按需求读画法图例和对应规范。提供可读的参考图片，不能只给另一个 Agent 的结论。更新Skill本身不隐含再次向DeepSeek或其他外部Agent提交。

按实际测试题选择范围：

- 现有素材／渲染复用：使用 demo-story.json、demo-strokes.json.gz，检查模板、参数、导出和真正逐笔绘制。这只能证明渲染链路。
- 新球员画法：查找或读取本人的具体时期全身照片，固定该照片的动作、五官与装备，创作相应画稿。比较全身和脸部。仅需两张画稿时，不增加整段生涯和无关统计。
- 新球员完整片：在前两项基础上核验生涯、时期队徽、奖杯及统计，再生成成片。
- 厚涂流程复用：使用 `assets/gouache-demo/story.json` 与同目录几何，按 gouache-workflow.md 验证；该流程与旧彩铅格式不同。画稿、正文、统计和队徽均需在换球员时替换，不能只改姓名。
- 逐章交付：导出指定范围，核对每章内容、独立起止和1秒停留，实际播放视频，不只交一个章节下拉框。

有图像生成工具时使用实际可用的生成／编辑能力。只有文件和代码工具时，可在明确的原生矢量试画中创作连续路径 SVG，须标明工具差异；它与使用同一种图像模型不是等条件比较。仅文本输出不能冒充图片、本地文件或已播放的动画。

测试限定在一个新的输出目录。不要更改 Skill、原版、账号配置或其他任务。对方报告实际文件、参考来源和时期、使用的工具、测试范围及失败。收到图片后检查：

1. 是指定球员本人，脸部、发型、年龄与姿态符合参考。
2. 笔法符合所选图例，概括和精画确有差别；粗线简笔画少笔、松散、轮廓不机械。
3. 要求动画时，实际落笔逐步累积、全部完成后停一秒；静态图片与动画验证分开记录。

收到拒绝、工具不可用或质量失败时如实记录。必要时给一次具体修正意见，再看实际产物。不能让对方宣称成功后直接计为通过，也不能以缺少图像工具的结果推断模型本身的绘画上限。
